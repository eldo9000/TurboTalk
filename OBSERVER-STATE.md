## Active development areas
The dominant arc since Run 2 is a multi-backend transcription architecture. A `TranscriptionBackend` trait was extracted with Whisper as the first concrete impl (TASK-57), then Moonshine and Parakeet scaffolds landed behind feature flags (TASK-58, TASK-59), then a user-facing backend-family selector was wired through `settings.rs`, the Settings tab, and onboarding Step 4 (TASK-60). The most recent two commits sit on top of that work: a fix that resolved the `ort` version conflict between `transcribe-rs` and `vad-rs` to actually activate Moonshine and Parakeet, and a UI follow-up that made the Models tab backend-aware and removed stale "not yet active" copy. In parallel, two quality filters landed earlier in the window — Silero VAD pre-filtering for whisper-server (TASK-56) and a hallucination-detection filter using compression ratio, trigram repetition, and non-letter signals (TASK-55). The streaming-chunked-transcription work referenced in user memory as "felt instant" (TASK-54) is on main but predates this window. A Windows dev-build workflow was added (`5bba507`), and v0.9.0 — the first confidently-shareable macOS release — shipped with a stable-name DMG asset and direct README download link. SESSION-STATUS notes no next action is pinned; macOS feature work is declared complete and the next named milestone is Windows/Linux porting (TASK-25/26) toward v1.0.

## Fragile / high-risk areas
`src-tauri/src/transcribe.rs` and the new `src-tauri/src/transcribe_backends/` tree are the highest-churn surface this window — five consecutive commits touched the backend abstraction, and the `ort` version pin conflict (`transcribe-rs 0.3.11` pinning `=2.0.0-rc.12` against `vad-rs 0.1.5` pinning `=2.0.0-rc.9`) was a documented blocker for two of the three new backends before commit `7bdb005` resolved it. The conflict is the kind of dependency-graph fragility that does not show up in tests and only surfaces when feature flags are flipped, which echoes the "refactor-induced flag loss" shape Run 2 named. The hotkey path also took a targeted fix this window (`8811e2e`: don't arm ptt_up suppression on hold-cancel in toggle mode), and the paste path added AX-based miss detection (`b7f8652` ... `b6b1f91`), both of which are exactly the surfaces Run 1 and Run 2 flagged as historically prone to subtle regressions. INVESTIGATION-LOG.md shows no new entries since Run 2 — the last entry is dated 2026-05-12, so the backend, VAD, hallucination-filter, and ort-conflict work all happened without log entries.

## Pattern watch
The "refactor-induced flag/parameter loss" shape Run 2 named did not recur this window, which is a positive signal — the backend-trait extraction (TASK-57) was an explicitly behavior-preserving refactor that landed clean and held. A new pattern shape is visible though: cross-crate dependency-pin conflicts as a blocker class. The `ort` version conflict gated two backends for multiple commits and was documented in source comments (`transcribe_backends/parakeet.rs` and `Cargo.toml`) rather than in KNOWN-PATTERNS or the investigation log. This is the second time a dependency-graph constraint has shaped the architecture (the SVE cmake probe hang on M4 in `docs/reference/KNOWN-BUG-CLASSES.md` was the first), suggesting a candidate pattern: "upstream pinned-version conflicts" as a recurring class. KNOWN-PATTERNS.md still does not exist; KNOWN-BUG-CLASSES.md exists with a single entry header.
